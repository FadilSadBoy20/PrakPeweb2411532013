B. Pertanyaan Analisis
1. Pada skenario 3 dan 4 Langkah D.2, status favorit tetap sama walaupun tampilan berganti dari grid ke list. Padahal RecipeGridCard dan RecipeTile adalah dua widget yang berbeda. Jelaskan mengapa, dengan mengaitkannya pada Modul 6.

Status favorit tidak berubah ketika tampilan berganti dari grid ke list karena pengelolaan data favorit dilakukan secara terpusat melalui FavoriteProvider, bukan disimpan secara terpisah pada masing-masing widget. Sesuai konsep app state pada Modul 6, FavoriteProvider yang menggunakan ChangeNotifier dibagikan ke seluruh aplikasi melalui MultiProvider. Ketika pengguna menekan tombol favorit, fungsi toggle() akan memperbarui daftar _items dan menjalankan notifyListeners() untuk memberi tahu perubahan tersebut. Dengan begitu, RecipeGridCard maupun RecipeTile dapat memperoleh status favorit yang sama melalui context.watch<FavoriteProvider>(), meskipun keduanya merupakan widget yang berbeda.

2. Di dalam loadingBuilder terdapat baris if (loadingProgress == null) return child;. Apa yang akan tampil jika baris tersebut dihapus? Jelaskan alasannya.

Apabila baris if (loadingProgress == null) return child; dihilangkan, gambar resep tidak akan ditampilkan meskipun proses pengunduhannya sudah selesai. Sebagai gantinya, aplikasi akan terus memperlihatkan tampilan loading berupa kotak dengan ikon Icons.restaurant_menu. Hal ini karena loadingBuilder akan terus dipanggil selama proses pemuatan gambar berlangsung. Ketika gambar berhasil diunduh sepenuhnya, nilai loadingProgress akan menjadi null. Kondisi tersebut digunakan sebagai tanda bahwa gambar sudah siap ditampilkan, sehingga widget child perlu dikembalikan agar gambar dapat muncul di layar.

3. Hitung berapa pixel foto thumbnail yang di-decode dengan dan tanpa cacheWidth: 168, jika foto asli dari server berukuran 1200 × 800 pixel.

Tanpa menggunakan cacheWidth:
Gambar akan di-decode dengan ukuran asli penuh yaitu 1200 × 800 pixel = 960.000 pixel.

Dengan menggunakan cacheWidth:
Ketika cacheWidth diset 168, Flutter akan men-decode gambar dengan lebar 168 pixel sambil mempertahankan aspect ratio. Tinggi akan dihitung proporsional: (800 / 1200) × 168 = 112 pixel. Total pixel yang di-decode: 168 × 112 = 18.816 pixel.

Dengan menggunakan cacheWidth, jumlah pixel yang di-decode berkurang dari 960.000 menjadi 18.816 pixel, menghemat sekitar 98% memori. Ini sangat efisien terutama saat menampilkan banyak thumbnail dalam list atau grid.

4. Logo memakai font Poppins. Bagaimana cara Flutter menemukan font tersebut?

Logo aplikasi menggunakan font Poppins yang dideklarasikan pada file pubspec.yaml di bagian fonts. Flutter akan mencari font tersebut di folder assets/fonts/ sesuai dengan path yang didefinisikan. Ketika aplikasi dijalankan, Flutter akan memuat font Poppins dan menggunakannya sebagai font family default untuk seluruh aplikasi karena dideklarasikan sebagai bagian dari theme pada MaterialApp di file main.dart. Proses ini melibatkan beberapa tahap: pertama, Flutter membaca konfigurasi pubspec.yaml dan memuat font dari assets, kedua, font didaftarkan ke dalam font tree Flutter, ketiga, widget Text yang menggunakan fontFamily: 'Poppins' atau TextStyle dengan fontFamily: 'Poppins' akan merujuk ke font tersebut, dan keempat, Flutter akan mencari font yang cocok berdasarkan nama family dan weight/style yang diminta.

C. Latihan
1. Latihan 1

Tambahkan deretan cuisine filter di bagian atas halaman utama menggunakan widget ChoiceChip.

a. Tambahkan state String? _cuisine di _HomePageState. Nilai null berarti semua cuisine.

Pada soal ini, kita diminta untuk menambahkan state bernama _cuisine dengan tipe data String? (nullable String) di dalam class _HomePageState. State ini berfungsi untuk menyimpan pilihan cuisine yang sedang aktif dipilih oleh user. Penggunaan tipe data nullable dipilih karena memiliki dua kondisi penting: ketika _cuisine bernilai null, artinya user memilih opsi "Semua" sehingga tidak ada filter yang diterapkan dan semua resep akan ditampilkan. Sedangkan ketika _cuisine berisi nilai tertentu seperti "Italian" atau "Asian", maka hanya resep dengan cuisine tersebut yang akan ditampilkan. State ini bersifat ephemeral atau lokal karena hanya HomePage yang membutuhkannya untuk keperluan filtering, sehingga tidak perlu disimpan secara global menggunakan Provider seperti state favorit atau tema. Ketika user menekan salah satu ChoiceChip, nilai _cuisine akan diubah menggunakan method setState() yang akan memicu rebuild widget dan melakukan filter ulang terhadap data resep yang ditampilkan.

b. Ambil daftar cuisine dari data, bukan ditulis manual, misalnya dummyRecipes.map((r) => r.cuisine).toSet().

Pada soal ini, kita diminta untuk mengambil daftar cuisine secara dinamis dari data dummyRecipes, bukan dengan cara hardcode atau menulis manual satu per satu. Pendekatan dinamis ini memiliki beberapa keunggulan penting yaitu fleksibilitas dimana jika data resep bertambah atau berkurang maka daftar cuisine akan otomatis menyesuaikan tanpa perlu modifikasi kode, menerapkan DRY principle (Don't Repeat Yourself) sehingga tidak ada duplikasi data di dua tempat berbeda, serta lebih maintainable karena developer tidak perlu mengupdate daftar cuisine secara manual ketika ada perubahan data. Teknik yang digunakan melibatkan tiga tahap transformasi data: pertama menggunakan .map((r) => r.cuisine) untuk mentransformasi setiap objek Recipe menjadi String yang berisi nama cuisine-nya saja, kedua menggunakan .toSet() untuk menghilangkan duplikasi karena beberapa resep memiliki cuisine yang sama misalnya Italian muncul dua kali, dan ketiga menggunakan .toList() untuk mengkonversi Set kembali menjadi List agar bisa diiterasi di dalam ListView. Dari 6 resep dummy yang ada, terdapat cuisine Italian sebanyak 2 kali, Asian 1 kali, American 1 kali, Mexican 1 kali, dan Mediterranean 1 kali, sehingga setelah proses .toSet() akan menghasilkan 5 cuisine unik yang siap ditampilkan sebagai ChoiceChip.

c. Ubah body menjadi Column: deretan chip di dalam SizedBox(height: 56) berisi ListView horizontal, lalu Expanded berisi list atau grid.

Pada soal ketiga ini, kita diminta untuk mengubah struktur body Scaffold dari widget tunggal (list atau grid) menjadi Column yang terdiri dari dua bagian utama. Bagian pertama adalah SizedBox dengan tinggi tetap 56 pixel yang berisi deretan ChoiceChip dalam ListView horizontal, dimana SizedBox digunakan untuk membatasi tinggi area chip agar tidak memakan terlalu banyak ruang layar, dan ListView dibuat horizontal dengan property scrollDirection: Axis.horizontal sehingga user bisa scroll ke samping jika chip tidak muat di layar. ListView ini diberi padding horizontal 16 pixel dan vertical 8 pixel untuk memberi jarak dari tepi layar agar terlihat lebih rapi. Di dalam ListView terdapat dua jenis ChoiceChip: chip pertama adalah chip "Semua" dengan kondisi selected: _cuisine == null yang berarti chip ini akan terseleksi ketika tidak ada filter aktif, dan ketika user menekan chip ini maka callback onSelected akan mengeksekusi setState(() => _cuisine = null) untuk mereset filter. Chip-chip selanjutnya dibuat secara dinamis menggunakan spread operator ...cuisines.map() yang akan mengiterasi setiap cuisine dan membuat ChoiceChip dengan label sesuai nama cuisine tersebut, kondisi selected: _cuisine == cuisine untuk mengecek apakah chip tersebut sedang aktif, dan callback onSelected yang akan mengeksekusi setState(() => _cuisine = cuisine) untuk mengaktifkan filter sesuai cuisine yang dipilih. Setiap chip dibungkus dengan Padding untuk memberi jarak 8 pixel di sebelah kanan agar tidak menempel satu sama lain. Bagian kedua dari Column adalah widget Expanded yang berisi list atau grid resep yang sudah difilter, dimana Expanded berfungsi untuk mengisi seluruh sisa ruang layar yang tersedia setelah dikurangi tinggi SizedBox chip di atasnya, sehingga list atau grid bisa scroll secara vertikal dengan leluasa.

d. Kirim data yang sudah difilter ke _buildList() dan _buildGrid().

Pada soal keempat, diminta untuk melakukan filtering terhadap data resep berdasarkan pilihan cuisine yang aktif, kemudian mengirim data hasil filter tersebut sebagai parameter ke method _buildList() dan _buildGrid(). Proses filtering dilakukan dengan membuat variabel filteredRecipes yang menggunakan conditional expression: jika _cuisine == null maka filteredRecipes akan berisi seluruh dummyRecipes tanpa filter karena user memilih "Semua", namun jika _cuisine memiliki nilai tertentu maka akan digunakan method .where((r) => r.cuisine == _cuisine) untuk memfilter hanya resep yang memiliki cuisine sesuai pilihan, dan hasilnya dikonversi ke List menggunakan .toList(). Data yang sudah difilter ini kemudian dikirim ke method _buildList() atau _buildGrid() sesuai mode tampilan yang aktif. Untuk mengakomodasi hal ini, signature kedua method tersebut harus diubah dari yang sebelumnya tidak menerima parameter menjadi menerima parameter bertipe List<Recipe> recipes. Method _buildList() akan membuat ListView.builder dengan itemCount: recipes.length yang menggunakan panjang data yang dikirim bukan dummyRecipes.length, dan pada itemBuilder akan menggunakan recipes[index] untuk menampilkan data yang sudah difilter. Demikian juga dengan method _buildGrid() yang membuat GridView.builder dengan itemCount: recipes.length dan menampilkan recipes[index] pada setiap grid item. Pendekatan ini membuat kedua method menjadi lebih reusable karena bisa menerima data berbeda-beda, logic filtering terpusat di satu tempat yaitu di dalam method build() sehingga mudah untuk maintenance, dan pemisahan concern antara logic filtering dengan logic presentation menjadi lebih jelas.

2. Latihan 2

Ubah halaman Favorit untuk menampilkan resep favorit dalam bentuk grid menggunakan widget GridView.builder.

Pada tugas kedua ini, kita diminta untuk mengubah halaman Favorit yang sebelumnya menampilkan resep favorit dalam bentuk list menjadi bentuk grid menggunakan widget GridView.builder. Implementasinya mirip dengan yang ada pada halaman HomePage, dimana digunakan properti crossAxisCount: 2 untuk membuat dua kolom, serta properti lain seperti mainAxisSpacing, crossAxisSpacing, dan childAspectRatio untuk mengatur tampilan grid. Data resep favorit diambil dari FavoriteProvider menggunakan context.watch<FavoriteProvider>().favorites yang akan otomatis diupdate ketika ada perubahan status favorit.

3. Latihan 3

Ubah halaman detail resep untuk menggunakan CustomScrollView dengan SliverAppBar yang menampilkan gambar resep sebagai header yang dapat collapse saat di-scroll.

Pada tugas ketiga ini, kita diminta untuk mengubah halaman detail resep menggunakan CustomScrollView dengan SliverAppBar untuk menciptakan efek collapsing header. SliverAppBar memiliki properti flexibleSpace yang berisi FlexibleSpaceBar dengan background RecipeImage untuk menampilkan gambar resep dalam ukuran besar. Properti expandedHeight menentukan tinggi maksimal AppBar saat expanded, sedangkan floating dan pinned mengatur behavior saat scroll. Saat user scroll ke bawah, gambar akan collapse dengan smooth transition dari posisi di bawah foto saat expanded ke posisi normal AppBar saat collapsed, menciptakan transisi visual yang smooth dan natural. Styling title menggunakan TextStyle dengan color: Colors.white agar teks terlihat jelas di atas foto yang mungkin memiliki warna beragam, dan yang sangat penting adalah penambahan shadows dengan Shadow widget yang memiliki offset (0, 1), blurRadius 3.0, dan color black45, sehingga teks memiliki bayangan hitam semi-transparan yang membuat teks tetap terbaca dengan jelas bahkan jika background foto memiliki area yang terang atau kontras rendah.

Kesimpulan

Praktikum 7 ini berhasil menambahkan fitur-fitur penting pada aplikasi ResepKu yang meningkatkan user experience secara signifikan. Implementasi GridView memberikan alternatif tampilan yang lebih modern dan efisien dalam menampilkan banyak resep, sementara image loading dengan error handling memastikan aplikasi tetap stabil meskipun terjadi masalah koneksi atau URL gambar tidak valid.

Penerapan asset management untuk font custom (Poppins) dan logo memberikan identitas visual yang kuat pada aplikasi. Penggunaan cacheWidth pada image loading terbukti sangat efektif dalam menghemat memori hingga 98%, yang sangat penting untuk performa aplikasi mobile. Penambahan fitur filtering berdasarkan cuisine menggunakan state lokal menunjukkan pemahaman yang baik tentang kapan menggunakan state management lokal (setState) versus global (Provider).

Latihan-latihan yang diberikan membantu memperdalam pemahaman tentang ChoiceChip untuk filtering, penggunaan ListView horizontal, Expanded widget untuk layout responsif, serta CustomScrollView dengan SliverAppBar untuk menciptakan UI yang lebih engaging dan professional. Implementasi halaman favorit dengan grid view dan halaman detail dengan collapsing header menunjukkan kemampuan mengintegrasikan berbagai widget Flutter untuk membangun aplikasi yang lengkap dan polished.

Dari praktikum ini dapat dipahami bahwa Flutter menyediakan berbagai widget dan teknik optimasi yang powerful untuk membangun aplikasi mobile yang tidak hanya fungsional, tetapi juga responsif, efisien, dan memiliki user experience yang excellent. Kombinasi antara state management yang tepat, optimasi performa, dan desain UI yang baik menghasilkan aplikasi ResepKu yang siap dikembangkan lebih lanjut dengan fitur-fitur tambahan.
