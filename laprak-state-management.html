State Management pada Aplikasi ResepKu

Praktikum 6 - Aplikasi Mobile

Aplikasi Mobile
Pendahuluan

Flutter menggunakan widget sebagai komponen utama dalam membangun tampilan aplikasi. Dalam pengembangan aplikasi yang kompleks, pengelolaan state (keadaan) menjadi sangat penting untuk memastikan data dapat diakses dan diperbarui dengan efisien di berbagai bagian aplikasi. State management yang baik memungkinkan aplikasi untuk merespons perubahan data secara real-time dan menjaga konsistensi antarmuka pengguna.

Pada praktikum ini, dilakukan penerapan State Management menggunakan Provider dan ChangeNotifier pada aplikasi ResepKu. Aplikasi ini menampilkan daftar resep makanan dengan fitur favorit, tema gelap/terang, dan penghapusan semua favorit. Melalui praktikum ini, diharapkan dapat dipahami perbedaan antara StatelessWidget dan StatefulWidget, penggunaan setState() untuk state lokal, serta implementasi Provider untuk state management global yang dapat diakses oleh berbagai halaman dan widget.

Tujuan

Praktikum ini bertujuan untuk:

  • Memahami konsep State Management dalam Flutter.
  • Membedakan penggunaan StatelessWidget dan StatefulWidget.
  • Menerapkan Provider dan ChangeNotifier untuk pengelolaan state global.
  • Mengimplementasikan fitur favorit dengan state yang dapat diakses di berbagai halaman.
  • Menerapkan theme management untuk dark mode dan light mode.
  • Memahami kapan menggunakan state lokal (setState) dan state global (Provider).
Langkah Praktikum
Bagian A: Membuat Struktur Dasar Aplikasi

Langkah pertama yang perlu dilakukan adalah membuat folder baru menggunakan Flutter Application dan membuat struktur folder serta file yang diperlukan:

  • lib/models/recipe.dart - Model data resep
  • lib/data/dummy_recipes.dart - Data dummy resep
  • lib/widgets/identity_footer.dart - Widget footer identitas
  • lib/main.dart - Entry point aplikasi
  • lib/pages/home_page.dart - Halaman utama daftar resep
  • lib/widgets/recipe_tile.dart - Widget item resep
  • lib/pages/detail_page.dart - Halaman detail resep

Tambahkan kode program pada masing-masing file sesuai dengan yang ada pada modul, kemudian jalankan aplikasi untuk memastikan struktur dasar berfungsi dengan baik.

Bagian B: Eksperimen dengan State Lokal

Pada bagian ini, dilakukan eksperimen dengan menambahkan fitur favorit menggunakan state lokal (setState). File recipe_tile.dart diubah menjadi StatefulWidget dengan menambahkan variabel _isFavorite dan icon hati yang dapat di-tap untuk mengubah status favorit.

Checkpoint 1: Tambahkan porsi pada halaman detail Classic Margherita Pizza hingga menjadi 6 porsi, sehingga total kalori menjadi 1800 kkal (hasil dari 300 x 6).

Ketika porsi berjumlah 1, tombol (-) akan dinonaktifkan secara otomatis. Hal ini disebabkan oleh kode program yang memastikan jumlah porsi tidak berkurang di bawah 1 menggunakan fungsi _removeServing() dengan kondisi if.

Analisis Masalah State Lokal

Berdasarkan eksperimen yang dilakukan, ditemukan beberapa masalah dengan penggunaan state lokal:

  • Jumlah resep favorit tidak dapat ditampilkan di AppBar HomePage karena variabel _isFavorite berada di dalam class _RecipeTileState, sehingga HomePage tidak memiliki akses langsung terhadap variabel tersebut.
  • Halaman detail tidak dapat mengetahui status favorit karena ketika navigasi dilakukan, hanya objek recipe yang dikirimkan melalui konstruktor tanpa menyertakan nilai _isFavorite.
  • Data favorit dibutuhkan di banyak tempat: daftar resep, badge, halaman detail, dan halaman Favorit, namun jika disimpan di dalam setiap tile, data tersebut tidak dapat dibaca oleh widget lain.

Kesimpulannya, solusi terbaik adalah memindahkan data favorit ke tingkat yang lebih tinggi menggunakan Provider agar dapat diakses oleh seluruh aplikasi.

Bagian C: Implementasi Provider untuk State Global

Mulai dari langkah C.1 hingga C.6, dilakukan implementasi Provider dengan langkah-langkah sebagai berikut:

  1. Memasang Provider: Tambahkan dependency provider ke pubspec.yaml
  2. Membuat FavoriteProvider: Buat file lib/providers/favorite_provider.dart yang berisi class yang extend ChangeNotifier untuk mengelola daftar favorit
  3. Mendaftarkan Provider di main.dart: Wrap MaterialApp dengan ChangeNotifierProvider
  4. Membaca dan Mengubah data favorit: Gunakan context.watch() untuk membaca dan context.read() untuk mengubah
  5. Membuat halaman Favorit: Buat favorite_page.dart yang menampilkan daftar resep favorit
  6. Menambahkan Badge jumlah favorit di AppBar: Buat widget badge yang menampilkan jumlah resep favorit

Checkpoint 2: Menguji aplikasi setelah melakukan Hot Restart dengan skenario pengujian berikut:

Pertanyaan Analisis
1. Mengapa ikon hati dapat berubah tetapi jumlah favorit tidak dapat ditampilkan di AppBar?

Pada eksperimen Bagian B.2, ikon hati dapat berubah ketika ditekan karena RecipeTile sudah menggunakan StatefulWidget dan fungsi setState() untuk mengubah nilai variabel _isFavorite dari false menjadi true atau sebaliknya. Namun, jumlah resep favorit tidak dapat ditampilkan secara langsung pada AppBar HomePage karena variabel _isFavorite hanya berada di dalam class _RecipeTileState, sehingga HomePage tidak dapat mengakses data tersebut.

Begitu juga dengan DetailPage, halaman ini tidak dapat mengetahui status favorit resep yang dibuka karena ketika navigasi dilakukan, hanya objek recipe yang dikirimkan melalui konstruktor, tanpa menyertakan nilai _isFavorite. Hal ini menunjukkan bahwa state lokal pada setiap tile tidak cukup untuk mengelola data favorit yang dibutuhkan oleh beberapa widget dan halaman sekaligus.

2. Mengapa jumlah porsi tetap menggunakan setState() dan tidak dimasukkan ke Provider?

Jumlah porsi tetap menggunakan setState() karena data tersebut hanya dibutuhkan pada halaman DetailPage dan tidak perlu diakses oleh halaman lain. Oleh karena itu, pengelolaan state secara lokal sudah cukup untuk mengatur perubahan jumlah porsi.

Hal ini dibuktikan pada skenario 6 Langkah C.7, ketika jumlah porsi diubah menjadi 2, kemudian pengguna kembali ke Home dan membuka resep yang sama, jumlah porsi akan kembali ke nilai awal sesuai data pada Recipe. Kondisi tersebut terjadi karena state lokal _servings ikut dibuang ketika halaman detail ditutup, sehingga saat halaman dibuka kembali, nilainya diinisialisasi ulang melalui initState(). Dengan demikian, penggunaan setState() lebih sesuai karena jumlah porsi tidak memerlukan penyimpanan state secara global.

3. Apa yang terjadi jika ChangeNotifierProvider dipindahkan ke dalam HomePage?

Apabila ChangeNotifierProvider dipindahkan dari main.dart ke dalam HomePage dengan posisi membungkus Scaffold, halaman Home masih dapat mengakses FavoriteProvider karena berada di dalam cakupan provider tersebut. Namun, ketika halaman Favorit dibuka, aplikasi akan mengalami error ProviderNotFoundException karena halaman Favorit merupakan route baru yang dikelola oleh Navigator dan tidak berada di dalam cakupan provider yang dipasang di dalam HomePage.

Hal ini terjadi karena posisi provider di dalam widget tree hanya mencakup widget turunannya, bukan seluruh halaman yang dikelola oleh Navigator. Oleh karena itu, ChangeNotifierProvider harus dikembalikan ke main.dart dan diletakkan di atas MaterialApp agar seluruh halaman, seperti Home, Detail, dan Favorit, dapat mengakses FavoriteProvider yang sama.

Latihan - Fitur Tambahan
1. Tema Gelap Terang

Menambahkan halaman Pengaturan yang berisi SwitchListTile "Mode gelap", yang mana ketika switch diaktifkan, seluruh aplikasi berubah ke tema gelap. Implementasi ini dilakukan dengan membuat beberapa file dan modifikasi:

lib/providers/theme_provider.dart

File ini adalah state management untuk tema aplikasi. Berisi class ThemeProvider yang extend ChangeNotifier dengan field private _themeMode bertipe ThemeMode dengan nilai default ThemeMode.system. Ada getter themeMode untuk membaca nilai dari luar, dan method toggleTheme yang menerima parameter boolean isDark untuk mengubah tema antara dark dan light mode. Setiap perubahan state akan memanggil notifyListeners() agar semua widget yang mendengarkan provider ini bisa rebuild dan menampilkan tema terbaru.

lib/pages/settings_page.dart

Halaman pengaturan yang berisi kontrol untuk mengubah tema. Dibuat sebagai StatelessWidget karena state dikelola oleh Provider bukan local state. Di dalam build method, kita watch ThemeProvider untuk mendapatkan status tema saat ini dan menentukan apakah isDark atau tidak. Halaman ini menampilkan SwitchListTile dengan title "Mode gelap", subtitle "Aktifkan tema gelap", dan icon yang berubah dinamis antara dark_mode dan light_mode sesuai status tema. Saat switch di-toggle, callback onChanged akan memanggil context.read untuk mengeksekusi method toggleTheme tanpa menyebabkan rebuild pada widget ini.

Modifikasi lib/main.dart

Pada file ini dilakukan tiga perubahan utama:

  1. Menambahkan import untuk ThemeProvider
  2. Mendaftarkan ThemeProvider ke dalam MultiProvider bersama dengan FavoriteProvider
  3. Memodifikasi class ResepKuApp dengan menambahkan watch ThemeProvider dan membaca themeMode, kemudian menambahkan parameter darkTheme dan themeMode pada MaterialApp

Modifikasi lib/pages/home_page.dart

Menambahkan IconButton baru di array actions AppBar untuk navigasi ke SettingsPage, memungkinkan user mengakses halaman pengaturan untuk mengubah tema.

Cara Kerja Sistem:

Alur kerjanya dimulai saat aplikasi pertama kali dibuka. MaterialApp membaca themeMode dari ThemeProvider yang defaultnya ThemeMode.system sehingga mengikuti pengaturan sistem. User melihat HomePage dengan tema default dan bisa klik tombol settings di AppBar. Setelah diklik, Navigator akan push ke SettingsPage. Di halaman settings ada switch "Mode gelap" yang saat di-toggle akan memanggil callback onChanged yang mengeksekusi context.read ThemeProvider untuk memanggil method toggleTheme. Method ini mengubah nilai _themeMode dan memanggil notifyListeners(). Semua widget yang watch ThemeProvider akan rebuild, termasuk MaterialApp di main.dart. MaterialApp menerima themeMode baru dan Flutter framework otomatis mengubah tema seluruh aplikasi secara real-time.

2. Menghapus Semua Favorit

Menambahkan fitur untuk menghapus semua resep favorit sekaligus dengan konfirmasi. Implementasi dilakukan dengan memodifikasi file lib/pages/favorite_page.dart:

Method _showClearConfirmationDialog

Method helper private ini bertanggung jawab menampilkan dialog konfirmasi sebelum menghapus semua favorit. Method ini menerima dua parameter yaitu BuildContext context untuk navigasi dan FavoriteProvider provider untuk memanggil method clear. Di dalamnya menggunakan showDialog yang menampilkan AlertDialog dengan title "Hapus Semua Favorit" dan content berisi pertanyaan konfirmasi. Dialog memiliki dua actions yaitu tombol Batal yang menutup dialog tanpa melakukan apa-apa dengan Navigator.pop, dan tombol Hapus yang memanggil provider.clear() untuk menghapus semua favorit kemudian menutup dialog.

Tombol Hapus Semua di AppBar

Di AppBar ditambahkan array actions yang berisi Consumer widget untuk FavoriteProvider. Penggunaan Consumer di sini penting karena kita perlu rebuild tombol saat jumlah favorit berubah untuk update status enabled/disabled. Di dalam builder Consumer, return IconButton dengan icon delete_sweep, tooltip "Hapus semua", dan onPressed yang menggunakan conditional expression. Jika favorite.count lebih besar dari nol maka onPressed berisi callback yang memanggil _showClearConfirmationDialog. Jika count sama dengan nol maka onPressed bernilai null yang membuat tombol otomatis disabled dengan warna greyed out.

Cara Kerja Sistem:

Alur kerja dimulai saat user membuka halaman Favorit. Consumer di AppBar akan membaca FavoriteProvider.count untuk menentukan apakah tombol "Hapus semua" aktif atau tidak. Jika ada favorit minimal satu item maka tombol aktif berwarna normal, jika kosong maka tombol greyed out dan tidak bisa diklik. Saat user klik tombol yang aktif, method _showClearConfirmationDialog dipanggil yang menampilkan AlertDialog dengan dua pilihan. Jika user klik tombol Batal maka Navigator.pop menutup dialog dan tidak ada perubahan data. Jika user klik tombol Hapus maka provider.clear() dipanggil yang menghapus semua item dari list _items di FavoriteProvider dan memanggil notifyListeners(). Setelah notifyListeners dipanggil, semua Consumer yang listen ke FavoriteProvider akan rebuild termasuk Consumer di AppBar yang membuat tombol menjadi disabled karena count sekarang nol, dan Consumer di body yang menampilkan empty state "Belum ada resep favorit". Badge di HomePage juga otomatis update menjadi hilang karena count nol.

Kesimpulan

Praktikum ini memberikan pemahaman mendalam tentang State Management dalam Flutter. Perbedaan antara state lokal (setState) dan state global (Provider) menjadi jelas melalui implementasi fitur favorit. State lokal cocok untuk data yang hanya dibutuhkan dalam satu widget atau halaman, seperti jumlah porsi dalam DetailPage. Sementara itu, state global menggunakan Provider sangat penting untuk data yang harus diakses oleh berbagai halaman dan widget, seperti daftar favorit yang dibutuhkan di HomePage, DetailPage, dan FavoritePage.

Implementasi Provider dengan ChangeNotifier memberikan solusi yang elegan untuk pengelolaan state yang dapat diakses secara global, dengan notifyListeners() yang secara otomatis memperbarui semua widget yang mendengarkan perubahan data. Penambahan fitur tema gelap/terang dan hapus semua favorit menunjukkan fleksibilitas Provider dalam mengelola berbagai jenis state dalam aplikasi. Dengan pemahaman ini, pengembangan aplikasi Flutter yang lebih kompleks dengan pengelolaan state yang efisien dapat dilakukan dengan lebih baik.
